<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → ntfy.sh | Untrusted public service; fetch POST carries user-entered message text |
| DOM → user | Message text entered by the user is echoed back in buttons/status |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | script.js DOM writes | mitigate | `textContent` only — grep gate `grep -c innerHTML script.js == 0` enforced in task 2. User-entered text never parsed as HTML. |
| T-02-02 | DoS (rate limit) | sendAlert to ntfy.sh | mitigate | Retry with backoff (3 attempts) and visible error status; prevents silent failure UX. |
| T-02-03 | Spoofing | ntfy topic (open access) | accept | Locked design decision (no auth). Topic secrecy documented in plan 04 README. |
| T-02-04 | Info Disclosure | message body (user content) | accept | Fire-and-forget design; messages are short family alerts, no PII expected; documented limitation. |
</threat_model>
